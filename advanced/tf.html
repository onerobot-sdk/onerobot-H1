TF 坐标系（tf2） ​

ROS 2 使用 tf2 查询坐标系之间的变换。接入前先确认设备上实际运行的模型与发布节点；导航、MoveIt 双臂规划、H1 整机显示使用的坐标系不能仅凭名称相似就互换。

坐标约定遵循 REP-103：机器人本体 X 前向、Y 左向、Z 向上。相机光学坐标系通常为 X 右、Y 下、Z 前，使用前检查消息的 header.frame_id 和实际外参。

按用途选择坐标系 ​

用途名称与入口适用范围
导航与底盘里程计map → odom → base_link；/odomSLAM 与底盘服务已启动，完整链以设备 /tf 为准
MoveP / MoveL 机械臂控制左右臂各自的模型根坐标系与 TCP 坐标系左右臂的轴向不同，详见机械臂控制
MoveIt 双臂规划left_base_link / right_base_link，末端 left_link7 / right_link7本站 MoveIt 页描述的 A1 双臂配置
H1 v1.4 整机模型模型根 base_link，臂段 Link_l0…Link_l7 / Link_r0…Link_r7机器人模型中的 URDF
H1 整机实时显示默认 h1/base_link、h1/Link_l7 等；/h1/joint_states已安装并启动独立 h1_description ROS 2 功能包的设备

h1/ 是整机显示节点默认添加的 TF frame 前缀，不改变 URDF 中的关节名。整机显示树与导航树是否相连，必须查询实际 TF；不要自行添加零变换把它们强行连接。

SLAM 提供 map → odom，底盘里程计提供 odom → base_link。不同固件或外部集成可能使用不同根帧，按 /odom.header.frame_id、/odom.child_frame_id 和 view_frames 结果确认。不要假定一定存在 base 或 base_footprint 中间帧，也不要在文档中的示意树上直接填写机械外参。

激光雷达、相机、IMU 等传感器的安装变换由配套 URDF 或外参发布节点提供。位置、旋转和 frame_id 必须与当前硬件及标定一致；不能用一组“典型值”代替设备标定。

MoveIt 与整机模型的命名 ​

两种模型的单臂均有 7 个转动关节，但名称不同：

对象MoveIt A1 双臂配置H1 v1.4 整机 URDF
左臂关节joint1-l 至 joint7-lleft_arm_joint_1 至 left_arm_joint_7
右臂关节joint1-r 至 joint7-rright_arm_joint_1 至 right_arm_joint_7
左臂连杆left_base_link → left_link1 → … → left_link7Link_l0 → Link_l1 → … → Link_l7
右臂连杆right_base_link → right_link1 → … → right_link7Link_r0 → Link_r1 → … → Link_r7
关节状态入口/joint_states独立 ROS 包合并为 /h1/joint_states

第 7 个臂关节也是转动关节，不能按“6 个转动关节 + 固定 joint7”理解本页的两种 7 轴模型。夹爪安装与手指连杆由各自 URDF 定义。

MoveIt 轨迹的 joint_names 必须匹配正在运行的 MoveIt 模型，详见 MoveIt 关节命名约定。整机显示适配器负责将各模块状态转换为整机模型关节，不能把 /h1/joint_states 的名称直接用于 MoveIt 轨迹。

发布节点与数据入口 ​

数据发布者 / 消费者检查重点
/tfSLAM、里程计、robot_state_publisher 等各父子变换的唯一发布者、时间戳和完整连通性
/tf_static固定外参节点、robot_state_publisher固定关节走静态变换，避免重复发布同一父子关系
/joint_states机械臂状态节点 → MoveIt / 对应模型发布节点关节名必须与实际加载的 URDF 一致
/h1/joint_statesh1_joint_state_adapter → h1_robot_state_publisher配套 ROS 包默认约 30 Hz，合并机械臂、头部、升降与夹爪
/h1/robot_descriptionh1_robot_state_publisher配套 ROS 包的整机描述话题；默认 TF 前缀 h1/

旧的 lift_odom → lift_base、head_odom → head_base 变换是否启用取决于固件。升降高度优先读取 /lift/joint_states，不要以旧版辅助里程计话题存在为前提，见升降反馈说明。

命令行检查 ​

以下命令只读取状态，不下发运动：

bash
# 查看实际 TF 树与发布节点
ros2 run tf2_tools view_frames
ros2 topic info /tf -v
ros2 topic echo /odom --once

# 查询导航链（SLAM 和底盘已启动时）
ros2 run tf2_ros tf2_echo map base_link

# 使用配套 h1_description ROS 包时检查整机显示链
ros2 topic info /h1/joint_states -v
ros2 run tf2_ros tf2_echo h1/base_link h1/Link_l7

# 收取静态变换的已发布值
ros2 topic echo /tf_static --qos-durability transient_local --once

程序中查询变换 ​

下面查询表达在 base_link 下的点到 map 的变换。帧必须实际存在且连通，节点需由 executor 正常处理订阅回调。

cpp
#include <tf2_ros/buffer.h>
#include <tf2_ros/transform_listener.h>

auto tf_buffer = std::make_shared<tf2_ros::Buffer>(node->get_clock());
auto tf_listener = std::make_shared<tf2_ros::TransformListener>(*tf_buffer);

if (tf_buffer->canTransform("map", "base_link",
                            tf2::TimePointZero,
                            tf2::durationFromSec(0.1))) {
  auto transform = tf_buffer->lookupTransform(
      "map", "base_link", tf2::TimePointZero);
  // 使用 transform.transform.translation / rotation
}
