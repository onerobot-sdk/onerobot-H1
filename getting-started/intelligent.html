智能版：连接与使用 ​

H1 智能版在 RK3576 主控之外增加 NVIDIA 计算板。开发电脑先连接 H1，再通过 RK3576 登录 NVIDIA 计算板；应用可以部署在 NVIDIA 计算板上，通过机器人接口完成二次开发。

本页适用于使用 原生 Zenoh（rmw_zenoh_cpp） 的智能版。标准版当前使用 DDS，开发环境见标准版：安装 ROS 2 Jazzy。

双板连接与地址 ​

连接位置用途地址规则
① RK3576 对外网口连接开发电脑或路由器网线直连默认 10.42.0.2；接入提供 DHCP 的路由器或电脑时，也可获得分配的 IP
② RK3576 内部网口（以下以 orin0 为例）经 USB 3.0 转网口模块、网线连接 NVIDIA 计算板；提供 DHCP交付说明中的默认地址为 192.168.251.1，可用下文命令核对设备实际配置
NVIDIA 计算板网口连接 RK3576 内部网络通过 DHCP 获取地址；192.168.251.37 仅为示例，登录前先查询

电脑网线直连时，将电脑对应网口的 IPv4 地址设为同网段，例如 10.42.0.1/24，子网掩码为 255.255.255.0。不要与机器人的 10.42.0.2 重复。

电脑和 H1 接入同一路由器时，使用路由器分配给 H1 的实际地址。后续 SSH、SCP 和电脑 Zenoh 配置中的 H1 地址都应一起替换。机器人热点及 WiFi 局域网的连接方式见SSH 远程登录机器人。

计算板联网方式 ​

NVIDIA 计算板安装在机器人内部，通过内部有线网络连接 RK3576 主控板。需要联网时，将机器人对外网口接入可访问互联网的有线网络，计算板通过主控共享网络，无需单独配置 Wi-Fi。

电脑网线直连机器人用于本地调试，不代表机器人已接入互联网。在计算板上下载依赖、获取源码前，先确保主控板已接入可上网的网络。后续登录仍按“开发电脑 → RK3576 主控板 → NVIDIA 计算板”的顺序进行。

登录 RK3576 和 NVIDIA 计算板 ​

1. 在开发电脑上登录 RK3576 ​

执行位置：开发电脑终端。 以下以网线直连为例：

bash
ping -c 4 10.42.0.2
ssh wlab@10.42.0.2
1
2

RK3576 用户名为 wlab，默认密码为 wlab；若已修改密码，使用修改后的密码。输入密码时终端不显示字符。首次连接时核对目标机器的 SSH 主机指纹，再确认连接。

登录成功后，这个终端已经在 RK3576 上执行命令。

2. 在 RK3576 上查询 NVIDIA 计算板的实际 IP ​

执行位置：已登录 RK3576 的终端。

bash
# 先查看网口名称及地址
ip -br addr

# 以下以内部网口 orin0 为例，按实际名称替换
ip -br addr show orin0

# 查看该网口上的邻居地址，找到 NVIDIA 计算板
ip neigh show dev orin0

网口名称区分大小写：若设备显示的是 Orin0 或其他名称，请按实际名称替换命令中的 orin0。也可使用 arp -a 查看邻居信息，注意区分内部网口与其他网口。邻居表是缓存，没有条目时先检查 NVIDIA 计算板是否上电、内部网线与 USB 转网口模块是否连接，以及 DHCP 是否分配了地址；不能仅凭空表判断 NVIDIA 计算板故障。

3. 从 RK3576 登录 NVIDIA 计算板 ​

执行位置：仍在 RK3576 终端。 将下面的示例地址替换为上一步查到的 NVIDIA 计算板 IP：

bash
ssh nvidia@192.168.251.37
1

NVIDIA 计算板用户名为 nvidia。交付环境配置了 RK3576 到 NVIDIA 计算板的免密登录；如果提示输入密码或认证失败，请核对设备交付的账号与 SSH 配置。这一免密配置适用于 RK3576 → NVIDIA 计算板，不等于电脑可以直接免密登录 NVIDIA 计算板。

进入 NVIDIA 计算板后，可用下面的只读命令确认当前用户、主机和架构：

bash
whoami
hostname
uname -m

3

嵌套登录时，在 NVIDIA 计算板输入一次 exit 返回 RK3576，再输入一次 exit 返回开发电脑。

传输文件与访问工具 ​

将文件上传到 RK3576 ​

执行位置：开发电脑新开的终端。 用实际文件替换 example.zip：

bash
scp ./example.zip wlab@10.42.0.2:~/
1

文件保存到 RK3576 的 /home/wlab/。传输整个目录时可以使用 scp -r ./project wlab@10.42.0.2:~/。

将文件继续传到 NVIDIA 计算板 ​

执行位置：RK3576 终端。 使用实际 NVIDIA 计算板 IP：

bash
scp ~/example.zip nvidia@192.168.251.37:~/
1

文件保存到 NVIDIA 计算板的 /home/nvidia/。进入 NVIDIA 计算板后，可在该目录下准备应用工作空间，按对应示例的依赖、编译和启动说明继续操作。

开发电脑的 Zenoh 环境 ​

本节所有安装、文件配置和 systemd 命令均在开发电脑上执行。 RK3576 和 NVIDIA 计算板使用设备交付时配置的通信环境。

电脑上的 ROS 2 节点通过本地 Zenoh router 连接 H1 的 Zenoh router，目标端口为 TCP 7447。仅设置 RMW_IMPLEMENTATION 还不够，需要完成下面的 router 配置。

1. 安装软件包 ​

开发电脑需要 Ubuntu 24.04 和 ROS 2 Jazzy。尚未安装 ROS 2 时，先按 ROS 2 Jazzy 官方 Ubuntu 安装说明配置软件源并安装 ROS 2，再继续本节。

沿用已配置的 ROS 软件源安装 Zenoh：

bash
sudo apt update
sudo apt install -y ros-jazzy-rmw-zenoh-cpp ros-jazzy-zenoh-cpp-vendor

source /opt/ros/jazzy/setup.bash
ros2 pkg prefix rmw_zenoh_cpp
dpkg-query -W ros-jazzy-rmw-zenoh-cpp

2. 配置电脑的 router ​

下面以网线直连为例。接入路由器时，先将 H1_IP 改成 H1 在局域网内的实际地址：

bash
H1_IP=10.42.0.2
sudo install -d -m 755 /etc/zenoh
sudo tee /etc/zenoh/router.env > /dev/null <<EOF
ZENOH_CONFIG_OVERRIDE='listen/endpoints=["tcp/127.0.0.1:7447"];connect/endpoints=["tcp/${H1_IP}:7447"];routing/router/peers_failover_brokering=true;transport/link/tx/queue/congestion_control/drop/wait_before_drop=1000000'
EOF
1
2
3
4
5

listen/endpoints 是电脑本地监听地址，connect/endpoints 是机器人地址。更换连接方式或 H1 的 IP 后，修改 /etc/zenoh/router.env 中的 connect/endpoints，然后重启电脑的 zenoh-router.service。

创建电脑的服务文件：

bash
sudo tee /etc/systemd/system/zenoh-router.service > /dev/null <<'EOF'
[Unit]
Description=H1 development PC Zenoh router
After=network.target
StartLimitIntervalSec=0

[Service]
Type=exec
Environment=ZENOH_ROUTER_CONFIG_URI=/opt/ros/jazzy/share/rmw_zenoh_cpp/config/DEFAULT_RMW_ZENOH_ROUTER_CONFIG.json5
Environment=RUST_LOG=zenoh=info
EnvironmentFile=/etc/zenoh/router.env
UnsetEnvironment=CYCLONEDDS_URI
ExecStart=/bin/bash -ec 'source /opt/ros/jazzy/setup.bash; exec /opt/ros/jazzy/lib/rmw_zenoh_cpp/rmw_zenohd'
Restart=on-failure
RestartSec=2s
TimeoutStopSec=5s

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable zenoh-router.service
sudo systemctl restart zenoh-router.service
systemctl status zenoh-router.service --no-pager

3. 在智能版开发终端加载环境 ​

将智能版环境保存为独立文件，方便同一台电脑按需调试标准版和智能版：

bash
cat > ~/h1-zenoh-env.sh <<'EOF'
source /opt/ros/jazzy/setup.bash
unset CYCLONEDDS_URI ZENOH_SESSION_CONFIG_URI ZENOH_CONFIG_OVERRIDE
export RMW_IMPLEMENTATION=rmw_zenoh_cpp
export ROS_DOMAIN_ID=0
export ZENOH_SESSION_CONFIG_URI=/opt/ros/jazzy/share/rmw_zenoh_cpp/config/DEFAULT_RMW_ZENOH_SESSION_CONFIG.json5
export ZENOH_CONFIG_OVERRIDE='transport/link/tx/queue/congestion_control/drop/wait_before_drop=1000000'
EOF

source ~/h1-zenoh-env.sh
echo "$RMW_IMPLEMENTATION"
echo "$ROS_DOMAIN_ID"

这里的 ROS_DOMAIN_ID=0 属于智能版通信配置。标准版继续按其 DDS 接入说明使用，切换回标准版时新开终端并加载标准版环境。

本节使用的配置文件与环境变量可参阅 rmw_zenoh 官方配置说明。

验证通信与排查 ​

在开发电脑上验证 ​

执行位置：已经加载智能版环境的电脑终端。 如果之前使用过其他 RMW，先停止旧的 ROS 2 CLI daemon，再检查话题：

bash
source ~/h1-zenoh-env.sh
ros2 daemon stop
ros2 topic list
ros2 topic echo /scan --once
1
2
3
4

能够收到 /scan 的 header、角度和距离数据，说明电脑已接收到机器人雷达消息。仅能 ping 或 SSH 登录成功，还不能确认 ROS 2 数据通信正常。

在 NVIDIA 计算板上验证 ​

执行位置：已登录 NVIDIA 计算板的终端。 使用板端交付环境：

bash
source /opt/ros/jazzy/setup.bash
echo "$RMW_IMPLEMENTATION"
ros2 topic echo /scan --once
1
2
3

RMW_IMPLEMENTATION 应为 rmw_zenoh_cpp。若为空或显示其他实现，先核对该设备的交付环境与 Shell 加载配置。收到雷达消息后，再按目标应用说明准备依赖和启动应用。

常见检查点 ​

现象先检查什么
电脑无法连接 10.42.0.2网线是否插在 H1 对外网口；电脑是否为 10.42.0.x/24；路由器连接时是否换成了实际 IP
RK3576 能登录，但找不到 NVIDIA 计算板NVIDIA 计算板上电、内部网线和 USB 转网口模块、内部网口地址及 DHCP 分配；网口名按实际设备核对，邻居缓存可能暂时没有条目
NVIDIA 计算板登录提示认证失败确认命令是在 RK3576 上执行，核对 NVIDIA 计算板实际 IP 与设备交付的 SSH 配置
NVIDIA 计算板无法联网请联系技术支持协助排查
SSH 正常，但电脑没有机器人话题电脑的 RMW 环境、ROS_DOMAIN_ID、router 目标 IP、TCP 7447 连通性及 router 日志
电脑 router 无法启动查看服务日志，核对配置路径、安装包版本及 7447 端口是否已有其他 router 占用
有话题但 /scan 没有数据核对机器人雷达服务、话题发布状态及通信链路；不能仅凭话题列表判定已连通

电脑 router 的只读检查命令：

bash
systemctl status zenoh-router.service --no-pager -l
journalctl -u zenoh-router.service -b -n 100 --no-pager

2

以上检查只读取状态和雷达消息。运动控制及应用运行按对应示例的前置条件操作；机器人服务说明见机内服务与重启。
