智能版：洗衣服场景示例 ​

本示例在 H1 智能版的 NVIDIA 计算板 上运行任务调度、视觉识别、已编译的动作程序和网页控制台，通过 H1 的 SDK 接口完成取衣、开门、放衣和关门流程。RK3576 继续提供机器人基础服务，开发电脑用于登录和操作网页。

流程共八步：搜索衣服 → 靠近衣服 → 抓取衣服 → 搜索洗衣机 → 靠近洗衣机 → 开门 → 放入衣服 → 关门并归位。当前流程不包含按下洗衣机启动按钮。

内容获取入口
运行包（ARM64）下载 h1-laundry-runtime-2026.10.21-rc1-linux-aarch64.tar.gz
运行包校验文件下载 SHA-256 校验文件
示例用途与操作说明洗衣示例 README
环境与运行依赖依赖说明
场景地图包下载洗衣场景地图 ZIP

设备与环境 ​

项目要求
机器人H1 智能版：RK3576 + NVIDIA 计算板；具备配套的导航、升降、双臂、夹爪与相机服务
深度相机头部、左臂、右臂三个位置均安装深度相机，使用 D435 或安思疆深度相机
应用运行位置NVIDIA 计算板；Ubuntu 24.04 ARM64、ROS 2 Jazzy、Python 3.12
通信使用智能版交付的原生 Zenoh环境；先完成双板连接、登录与通信验证
视觉随运行包提供三类别 ONNX 模型；使用 OpenCV DNN CPU 推理，当前未启用 MobileSAM
首次安装设备已安装 ROS 2 Jazzy 和所需系统运行库；Python 依赖可从随包 wheelhouse/ 离线安装，无需编译业务 C++ 代码

相机需要持续提供彩色图、深度图、内参及外参。换相机型号后应核对设备固件提供的话题、深度单位与标定，不能仅靠型号名称判断可以直接替换。当前配置文件为 install/h1_laundry/share/h1_laundry/config/default.yaml，其中三个相机入口为 head2、left、right。

部署前先完成智能版的双板连接与通信检查，再按下文安装应用、检查模型并完成定位与单步操作。设备重启后，应确认通信服务正常、相机图像与机器人状态持续更新，再启动真机流程；通信未就绪时，可先使用 mock 模式查看页面。

场景搭建与尺寸核对 ​

按下图布置沙发和洗衣机，准备待抓取衣物及供右腕相机识别的洗衣机红色标记。场景布置完成后，实际量测并记录下面六项尺寸，不要只凭目测摆放。

以下“上、下、左、右”均按示意图方向理解。

测量项目要求
房间左边界至右边界上、中、下三个位置分别量测：3 m ± 0.5 cm
房间上边界至下边界左、中、右三个位置分别量测：3 m ± 0.5 cm
房间左边界至沙发右边缘72～72.25 cm
沙发下边缘至房间下边界35 cm ± 0.25 cm
房间上边界至洗衣机上边缘40 cm ± 0.25 cm
洗衣机左边缘至房间右边界60 cm ± 0.25 cm

图中的原点仅作位置参考，算法已有预设，不需要另外布置原点标记，也不要据此把机器人随意搬到圆圈位置。未标注的沙发长度、洗衣机尺寸等不能按图片比例推算；红色标记的位置、动作点位、手眼标定和夹爪参数须与交付场景匹配。

通过 8090 导入地图 ​

先完成场景搭建，再导入配套地图。地图与本示例的场景、动作参数配套，不能当作任意房间的通用地图。

  1. 下载场景地图 ZIP，保持原始 ZIP，无需解压或重新打包。
  2. 在开发电脑浏览器打开 http://<机器人 IP>:8090/。网线直连示例为 http://10.42.0.2:8090/，这里使用 H1 的对外地址。
  3. 进入 算法测试 → 地图，找到 导入地图包。
  4. 点击 选择文件，选中地图 ZIP，再点击 导入地图，确认替换当前地图。若需保留现场地图，先导出备份。
  5. 页面显示“已下发地图导入”后，核对地图画面与元信息已更新，再进入 定位页启动定位并确认结果。

“已下发”表示导入请求已经发送，不等于地图已成功生效。建图、导航或机械臂老化测试进行中时，先结束对应任务，再导入地图。定位未成功时不要启动洗衣流程。

运行包中也包含同一地图，路径为 maps/h1-laundry-map.zip，大小为 2,682 字节。页面下载保持原始文件内容，其 SHA-256 为：

在 NVIDIA 计算板上部署运行包 ​

以下命令在 NVIDIA 计算板的 Bash 终端执行。先按智能版登录说明进入 NVIDIA 计算板，使用新的目录部署，保留已有可运行的旧目录。

1. 下载、校验与解压 ​

下载上表中的运行包和对应 .sha256 文件，放在 NVIDIA 计算板的同一目录。也可先在开发电脑下载，再通过文件传输工具复制过去。进入下载目录后执行：

bash
sha256sum -c h1-laundry-runtime-2026.10.21-rc1-linux-aarch64.tar.gz.sha256
# 使用未部署过的新目录，避免覆盖旧版本
mkdir h1-laundry-2026.10.21-rc1
tar -xzf h1-laundry-runtime-2026.10.21-rc1-linux-aarch64.tar.gz \
  -C h1-laundry-2026.10.21-rc1
cd h1-laundry-2026.10.21-rc1/h1-laundry-runtime
sha256sum -c assets.sha256

两次校验均应通过。保留运行包的完整目录结构，包括 install/、scripts/、config/、wheelhouse/、maps/ 和 licenses/。本包已包含六个 ROS 包的运行文件、动态库、接口、网页、模型和 URDF，无需安装 colcon 或重新编译。GitHub 的 Code → Download ZIP 仅下载仓库中的示例和说明，不包含这个 Release 运行包。

后续命令均在解压后的 h1-laundry-runtime/ 根目录执行。不要复制其他目录的 .venv/；应在最终运行位置创建 Python 环境，移动运行包后需重新创建。

test -f /opt/ros/jazzy/setup.bash
test -f config/local.env || cp config/local.env.example config/local.env
bash scripts/check_system.sh

环境应为 Ubuntu 24.04 / noble、arm64、Python 3.12.x，并已预装 ROS 2 Jazzy。check_system.sh 只读检查系统包，打印缺失项与安装建议，不执行安装。本包不包含系统镜像或 ROS、apt 系统包的离线安装介质。

本示例沿用智能版交付的原生 Zenoh 环境。启动脚本读取 config/local.env，核对其中的 RMW_IMPLEMENTATION=rmw_zenoh_cpp、ROS_DOMAIN_ID=0 与交付设备匹配。保留设备的 router/session 配置，不把标准版的 DDS 配置复制进来。连接及通信验证见智能版：连接与使用。

3. 安装 Python 依赖与离线检查 ​

bash
bash scripts/setup_python.sh
.venv/bin/python -m pip check
bash scripts/doctor.sh
1
2

安装脚本在当前运行包目录创建独立的 .venv，默认从随包 wheelhouse/ 离线安装固定版本的依赖。pip check 应显示 No broken requirements found.。不要混入其他电脑的 Python 环境或替换随包的运动学动态库。

doctor.sh 检查本地资源、消息类型支持、动态库及一次实际 ONNX 推理，不连接 ROS 图或下发机器人命令。检查通过后，先运行模拟页面，再核对真机话题、图像和状态。完整依赖与排障见运行包依赖说明。

启动页面与 SSH 访问 ​

1. 先查看模拟页面 ​

执行位置：NVIDIA 计算板。

bash
bash scripts/run_mock.sh
1

mock 用于检查网页和模拟流程，不连接真机控制链路。保持这个终端运行。

2. 在电脑建立 SSH 隧道 ​

执行位置：开发电脑另一个终端。 下面是网线直连 H1、NVIDIA 计算板示例地址为 192.168.251.37 的写法；先查询并替换实际 NVIDIA 计算板 IP：

bash
ssh -N -J wlab@10.42.0.2 \
  -L 8088:127.0.0.1:8088 nvidia@192.168.251.37
1
2

连接后终端保持等待是正常现象。在电脑浏览器打开 http://127.0.0.1:8088/。

H1 接入路由器时，将 10.42.0.2 替换为 H1 的实际地址。此命令需要开发电脑能够分别完成到 H1、NVIDIA 计算板的 SSH 认证；RK3576 上已有的免密登录并不会自动授权开发电脑。如果本地 8088 已被占用，可把 -L 的第一项改为 18088，再访问 http://127.0.0.1:18088/。

网页默认只监听 NVIDIA 计算板的 127.0.0.1:8088，通过 SSH 隧道访问即可。真机网页的监听设置位于 install/h1_laundry/share/h1_laundry/config/default.yaml 的 server.host、server.port；已有 runtime/config_overrides.yaml 中的 server 配置会覆盖默认值。

真机运行与八步验收 ​

场景尺寸、地图和相机准备好后，先停止 mock（Ctrl+C）。mock 与 live 不要同时运行；开发电脑、RK3576 上也不要同时运行另一套洗衣任务节点。

1. 配置真机开关并启动 ​

在运行包的 runtime/config_overrides.yaml 中合并下面的配置；文件不存在时创建，已有参数保留：

yaml
safety:
  control_enabled: true
1
2

回到 NVIDIA 计算板终端：

bash
bash scripts/run_live.sh
1

启动脚本同时启动 C++ 动作节点与 Python 网页/视觉服务。继续通过同一个 SSH 隧道访问网页。

2. 定位、图像与解锁 ​

先确认地图匹配并定位成功，头部、左腕、右腕图像与识别结果正常，模型状态为就绪。网页的“启动定位”使用配套的充电位置初始化流程，需要机器人处于该方式适用的位置；已下发定位命令不代表定位成功，以定位反馈为准。

确认动作区域清空、物理急停可用后，再在网页点击 真机解锁并输入 解锁真机。先逐项验收八步，确认点位与反馈正确后再运行全流程。

步骤功能
1搜索衣服
2靠近衣服
3抓取衣服
4搜索洗衣机
5靠近洗衣机
6识别红色标记并开门
7放入衣服
8关门、后退、双臂与升降复位，并返回流程起点

异常时使用网页“停止”结束任务；物理急停用于现场紧急情况。网络断连告警不能代替机器人急停。

参数与问题排查 ​

文件或入口用途
install/grasp/share/grasp/config/grasp_params.yaml动作点位、机械臂姿态及运动参数
install/h1_laundry/share/h1_laundry/config/default.yaml视觉、话题、网页与流程配置
config/local.env当前设备的运行环境；保留在本机
runtime/config_overrides.yaml网页保存的本机覆盖参数
网页“导出诊断包”收集运行状态与故障信息

若页面无法打开，在 NVIDIA 计算板的运行包根目录执行：

bash
bash scripts/export_diagnostics.sh
1

日志位于 runtime/log/，运行记录位于 runtime/diagnostics/。停止应用后修改默认配置，再重新启动；网页保存的参数进入运行覆盖文件。修改运动参数或更换机器人、场景后，应重新核对点位、机械臂型号、手眼标定和夹爪参数，并进行单步验证。

升级时保留旧运行包及其 runtime/，把新版解压到另一目录，重新创建 .venv，完成离线检查、模拟预览及现场验收后再切换。不要在任务执行中替换运行文件。
