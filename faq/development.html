SDK 开发接入 ​

完整接口说明见本站的硬件参考、软件接口、高级功能与系统诊断章节。

开发环境：Ubuntu + ROS2 Jazzy，开发语言 C++ / Python。以下为高频接入问题，完整接口以 SDK 文档为准。

环境与通用约定 ​

详细说明：设备信息与开发环境。

Q47. 怎么读取机器人的设备信息（型号 / 序列号）？ ​

订阅 /device_info（std_msgs/msg/String，约 1 Hz），data 是 JSON，含设备型号、设备 ID、序列号等：

bash
ros2 topic echo /device_info
1

整机固件版本可在网络配置工具「状态」页或出厂与跑机测试工具左侧栏底部的「软件版本」查看，也可通过只读 /api/system 查询，见固件版本查询。自定义机器人 ID 与由 MAC 派生的设备 ID 也不同，见设备标识说明。

Q48. 为什么很多控制话题都是 std_msgs/msg/String？命令行怎么发这种 JSON？ ​

机械臂、灯板、眼睛、SLAM、导航、人脸/手势/动作等指令普遍用 String 的 data 字段承载一段 JSON，订阅端需自行 json.loads。命令行发布时要对内层 JSON 的双引号转义；代码里建议用 JSON 库序列化后再填入 String.data。

bash
ros2 topic pub --once /eyes/expression std_msgs/msg/String "{data: '{\"target\":\"both\",\"expression_id\":1}'}"
1

传感器与相机 ​

详细说明：传感器接口。

Q49. 有哪些相机话题？RGB 和深度分别是什么格式？ ​

头部广角使用 /head/camera/rgb，左右相机使用 /left/camera/rgb、/right/camera/rgb。头部 D435 是选配，安装后才提供 /head2/camera/rgb 和 /head2/camera/depth；左右相机也取决于交付配置。

RGB 为 sensor_msgs/msg/CompressedImage（JPEG）；D435 深度为 sensor_msgs/msg/Image（16UC1，未对齐到彩色）。/<相机名>/camera/info 提供相机信息，但存在未标定的全零矩阵时不能直接用于测距，详见CameraInfo 标定有效性。

Q50. 订阅了相机话题，程序不报错但一帧都收不到，为什么？ ​

rgb/depth 使用 BEST_EFFORT（SensorDataQoS），若用默认的 RELIABLE 订阅会因 QoS 不兼容静默收不到任何数据。订阅端必须用 best-effort（C++ rclcpp::SensorDataQoS()，Python qos_profile_sensor_data）。另外相机仅在有订阅者时才出图，首 1~2 帧略有延迟属正常。

Q51. 怎么判断相机是否在线 / 掉帧？ ​

订阅 /<相机名>/camera/fps（std_msgs/msg/Float32，约 1Hz）看实测帧率，掉线/停图时发 0。注意"无订阅者时不出图、fps=0"是省电的正常现象，不代表故障。

Q52. 激光、IMU、碰撞、超声、声源、电池、充电桩数据怎么读？ ​

激光 /scan、IMU /imu、前碰撞 /front_bumper(Bool)、超声 /ultrasound_distance(Range)、声源角 /audio/doa(JSON，向左为正)、电池 /battery/state(电压/电流/SOC/温度)、充电桩 /chargeic_state(UInt32 位域：Bit24-31 在桩、Bit16-23 充电中、Bit0-15 充电电流 mA)。

Q53. 语音能力（识别、播报、放音频）怎么对接？ ​

ASR 结果 /asr/result（text/is_final）；LLM 回复 /llm/response、TTS 播报 /tts/text 为流式追加（拼 delta，is_end:true 结束，靠 session_id 关联）；放本地音频向 /audio/play 发 JSON（file_path/volume/loop），状态看 /audio/status；/asr/cmd 的 mute/unmute 停/恢复对话。

执行器控制 ​

详细说明：执行器接口。

Q54. 底盘怎么控制前进/后退/旋转？里程计在哪读？ ​

向 /cmd_vel（geometry_msgs/msg/Twist）发速度，linear.x 前后、angular.z 左旋(+)/右旋(-)；位姿速度读 /odom。

下例会让底盘前进。执行前确认运动范围内无人、无障碍，物理急停可触达。

bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.2}, angular: {z: 0.0}}"
1

Ctrl+C 只会停止命令发布，不能据此确认底盘已停。退出后发送零速度并观察机器人停止；异常时立即使用物理急停：

bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.0}}"
1

Q55. 升降机构怎么控制？能指定绝对高度和速度吗？ ​

速度控制使用 /lift/cmd_vel（linear.z 上升为正）；绝对高度使用 /lift/joint_states/update：name: ["lift_joint"]，position 为离地高度（米，约 0.4–1.3 m），可选 velocity 指定电机转速（30–800 RPM，默认 400）。

当前高度优先读取 /lift/joint_states，报警读取 /lift/alarm。旧 /lift/odom 是否发布取决于固件，且旧报文可能没有有效姿态，见升降反馈与兼容性。

Q56. 头部怎么控制？为什么发出去的方向和实际反了？ ​

速度控制 /head/cmd_vel：angular.y 负=抬头/正=低头，angular.z 负=左转/正=右转；绝对角度 /head/joint_states/update（head_pitch_joint/head_yaw_joint，弧度）：position 正=抬头/左转。⚠️ 速度控制与绝对角度控制的方向符号相反（底层伺服正方向定义不同），这是最常见踩坑点。

Q57. 机械臂 MoveJ / MoveP / MoveL 怎么发？三者区别？ ​

向左右臂各自的 movej、movep、movel 话题发送由 String 承载的 JSON（例如 /left_arm/movej，完整列表见执行器接口）。MoveJ 给出 7 个关节角（rad）；MoveP / MoveL 给出末端位置和姿态。MoveP 通过 IK 求解关节目标后执行关节轨迹，MoveL 则沿笛卡尔空间中的直线路径运动。

MoveP / MoveL 以对应机械臂的模型根坐标系为参考，左右臂的轴向不同；TCP 坐标系固定在末端并随末端姿态旋转。具体轴向见机械臂控制。speed_scale 的取值范围为 [0.01, 5.0]，缺省值为 1.0。⚠️ 运动前确保范围内无人无障碍、急停可触达，首次测试用低速。

Q58. 机械臂执行成功/失败怎么知道？运动中怎么急停？ ​

订阅 /arm_diagnostics：name 为 left_arm/right_arm，level=0 完成、level=2 失败。停止用 /left_arm/stop、/right_arm/stop（std_msgs/msg/Empty），/action/stop 可同时中断左右臂。（/movej_left_angle 等为遗弃接口，新集成勿用。）

Q59. 4 个灯板怎么控制颜色/亮度/闪烁？ ​

向 /light_board/control 发 JSON，boards 数组固定 4 项（对应灯板 1-4），每项含 color（十六进制）、brightness（0-100）、blink_hz（0 常亮）；不控制的灯板设 null 跳过。

Q60. 怎么读升降/头部的限位、堵转、报警？ ​

限位 /body/limit_switch（6 路 JSON）、头部堵转 /head/stall、升降报警 /lift/alarm（码 0=正常）。⚠️ 这三个话题都是 transient_local 锁存，订阅时 QoS 必须匹配（--qos-durability transient_local）才能收到最新值。

Q61. 眼睛表情怎么切换？能上传自定义表情吗？ ​

表情向 /eyes/expression 发 {"target":"both|left|right","expression_id":N}，亮度 /eyes/brightness（1-100），状态看 /eyes/state。自定义表情用资源包（manifest.json+GIF 打 zip）：拷到机器人后向 /eyes/resource 发 upload→activate，反馈看 /eyes/resource_status。

SLAM 建图与地图管理 ​

详细说明：SLAM 接口。

Q62. 怎么触发/结束建图？地图存哪？ ​

向 /slam/cmd 发 {"cmd":"start_mapping","detail":{"from_where":"charge"}} 开始、{"cmd":"stop_mapping"} 结束并保存（存到 /data/slam/map.pbstream）；建图状态看 slam/mapping_status，预览 /map（1Hz）。建图中可随时 {"cmd":"save_map"} 保存而不结束。

Q63. 建好的地图怎么导出，导入到另一台设备？ ​

导出调服务 /map_server/package（Trigger）得到 zip 路径；导入向 /map_server/setmap 发 zip 的绝对路径（清空当前→解压写入），导入后可直接 start_locating。删除地图用 {"cmd":"delete_map"}（需 SLAM 处于 IDLE）。

Q64. 怎么开始定位？没有地图会怎样？ ​

向 /slam/cmd 发 {"cmd":"start_locating","detail":{"from_where":"charge"}} 加载地图并重定位；若无已保存地图会直接报故障。想从指定位姿起，用 start 指令带 from_where:"given_pose" + x/y/yaw。定位状态看 slam/locating_status（locating_success 为成功，失败带 reason）。

Q65. 怎么实时获取当前位姿和 SLAM 状态？ ​

位姿订阅 slam/pose（geometry_msgs/msg/PoseStamped，frame_id: map），在定位/建图初始化完成后以约 50 Hz 持续发布。

slam/status、slam/mapping_status、slam/locating_status 是状态变化时发布的话题；需要立即取状态时，向相应同步话题发送 std_msgs/msg/Empty。同步接口不会代替位姿流，也不保证未初始化时有位姿。对应关系见SLAM 话题总览。栅格地图可通过 map_server/map（nav_msgs/srv/GetMap）查询。

Q66. 我发了 SLAM 指令但没反应 / 被忽略？ ​

各指令有前置状态：start* 仅在 IDLE、resume 仅在 PAUSE、save_map 需非 IDLE、delete_map 需 IDLE，不满足时指令被忽略。FAULT 下只接受 reset；过渡态（STARTING/PAUSING 等）不接受新指令。

导航 ​

详细说明：导航接口。

Q67. 怎么下发一个导航目标点？ ​

向 /start_task_v2 发 JSON：type:"goto_pose"，detail.pose:[x,y,yaw]（地图系，米/弧度），is_accurate_pose 控制精确/近似到达。默认导航含 A* 全局规划 + 软碰撞避障。调试可直接向 /goal_pose（PoseStamped）发单点。每个任务务必带唯一 task_id 以匹配反馈。

Q68. /start_task_v2_straight 和 /start_task_v2 有什么区别？ ​

消息格式相同，只切换 topic。⚠️ /start_task_v2_straight 走起点→终点直线、完全不避障，调用方必须先确认直线上无任何障碍物，仅用于回充上桩、短距精确直行。一般导航请用 /start_task_v2。多点巡航用 type:"follow_path"（detail.path 给点序列）。

Q69. 自动回充怎么做？ ​

两阶段：先 type:"goto_base"（base_type:"charge"，带充电座 pose）导航到桩前预备点；等 /task_status_v2 返回 success 后，再发 type:"enter_base" 执行精对位上桩。注意 goto_base 本身不上桩，pose 不可省略。

Q70. 导航任务状态怎么读？怎么中途停止？ ​

订阅 /task_status_v2：status 为 idle/running/success/fail/stop，失败看 fail_reason（unreachable / invalid detail / stop）。停止向 /task_ctrl_v2 发 {"task_id":"<同下发>","cmd":"stop"}。

Q71. 有没有 Nav2 标准接口做路径规划 / 查代价地图？ ​

有：路径规划服务 /planner_server/get_plan（GetPlan，start/goal 用 frame_id:map）、校验 /is_path_valid；代价地图订阅 /global_costmap/costmap_raw、/local_costmap/costmap_raw，清空用 /…/clear_entirely_*_costmap。

高级功能 ​

详细说明：MoveIt2 接口。

Q72. 人脸识别怎么用？怎么把新面孔注册成已知用户？ ​

订阅 /face/result（std_msgs/msg/String 内的 JSON），模块使用头部广角相机，默认处理频率约 10 Hz。每个完成的识别周期都会发布；faces 同时包含实时追踪人脸和历史暂存的 pending 条目。

无人脸时，faces 可能为空，也可能只含历史 pending。数组非空不等于当前有人，也不能把历史 pending 条目当作实时检测结果。

新面孔注册：向 /face/cmd 发 {"cmd":"register","detail":{"user_id":"...","pending_id":"..."}}，反馈看 /face/status；另支持查询与删除。字段和示例见人脸识别。

Q73. 手势识别怎么订阅？支持哪些手势？为什么 /gesture/types 收不到？ ​

结果订阅 /gesture/result（gesture/score/bbox），支持列表在 /gesture/types。⚠️ /gesture/types 用 RELIABLE + TRANSIENT_LOCAL，订阅端 QoS 不匹配就收不到。支持 yeah/thumbup/okay/rock/heart/stop/mute/wave（部分需 score≥0.9，各有冷却）。也可用任务编排 wait_for_gesture 等待指定手势。

Q74. 用 MoveIt2 控制双臂，规划组/关节怎么命名？速度怎么设？error_code 怎么看？ ​

本 SDK 的 MoveIt 文档对应 A1 双臂规划配置：left_arm、right_arm 各 7 自由度，both_arms 为 14；关节名为 joint1-l 至 joint7-l、joint1-r 至 joint7-r。H1 v1.4 整机显示模型使用另一套名称，不能直接替换到 MoveIt 轨迹中。

速度使用 max_velocity_scaling_factor，首次从 0.1 等低速值开始。MoveIt 的 error_code.val 中，1 为成功、-1 为规划失败、-6 为超时、-31 为无 IK 解；碰撞按起点、目标等具体错误区分。它与 FollowJointTrajectory 的错误码不同。

完整规划组、命名姿态和错误码见MoveIt2 运动控制。

Q75. 坐标系是怎么约定的？各类任务该用哪个帧？ ​

机器人本体遵循 REP-103（X 前、Y 左、Z 上）。导航使用 map → odom → base_link 链，实际连通性与帧名以运行中的 TF 为准。

MoveIt 目标位姿使用其规划模型里的参考帧和末端 link；配套整机显示 ROS 包默认使用 h1/ 前缀。不能把两套模型的连杆名混用，也不要假定两棵树自动相连。完整命名、查询命令与适用范围见TF 坐标系。

Q76. 有哪些预置动作可直接调用？怎么执行/查列表/停止？ ​

向 /action/execute 发 {"action_id":"salute","speed_scale":1.0} 执行（home/wave/salute/open_arms 等）；/action/query 查列表；状态订阅 /action/status（失败带 fail_reason）；/action/stop 中断左右臂。⚠️ 执行前确认范围内无人无易碰物、周围≥1m、电量>30%、急停可触达；人员附近 speed_scale≤0.6，首次≤0.3。

系统诊断与错误码 ​

详细说明：系统诊断接口。

Q77. 怎么一站式监控整机健康、判断"现在能不能派任务"？ ​

订阅 /diagnostics（DiagnosticArray，1Hz，TRANSIENT_LOCAL）。status[0] 是整机汇总 overall，看 system_level 和 task_allowed——关键模块出现 ERROR/FATAL/STALE 时 task_allowed=false，active_faults 列出活动故障。事件变化另发 /diagnostic_events。

Q78. /diagnostics 字段怎么解析？诊断等级 level 含义？ ​

values 里 faults/metrics/counts/active_faults 等是 JSON 字符串，需再 json.loads。等级：0=OK、1=WARN、2=ERROR、3=STALE。⚠️ 部分 Python 环境里 level 可能是 bytes，比较前先转 int。注意 /arm_diagnostics 是执行结果语义（0=完成、2=失败），与健康等级不同。

Q79. 常见的电机/关节/传感器错误码有哪些？ ​

电机与关节常见：motor overtemperature/overcurrent、motor stall detected、joint limit reached、encoder fault、CAN communication timeout（均 ERROR）。传感器：device not found、rate x below y（频率过低 WARN）、no data（STALE）。升降电机另有独立报警码（/lift/alarm，如 7=相位过流、10=编码器错误）。

Q80. 发现故障后怎么清除？有统一清故障接口吗？ ​

诊断节点只发布诊断、不提供统一清故障服务。清故障用各模块专用接口，例如升降堵转报警：ros2 topic pub /body_general_control std_msgs/msg/Int32 'data: 1' -1（data:1 清升降报警、2 升降校准、3 头部校准）。
