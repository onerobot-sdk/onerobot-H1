导航 NAV ​

提供点对点导航服务。

H1 自有导航接口 ​

话题消息类型方向说明
/start_task_v2std_msgs/msg/String发布（下发）导航任务下发（A* 规划 + 路径跟踪 + 软碰撞避障，默认）
/start_task_v2_straightstd_msgs/msg/String发布（下发）导航任务下发（直线插值路径 + 直线跟踪，不避障）
/task_ctrl_v2std_msgs/msg/String发布（下发）任务控制（停止等）
/task_status_v2std_msgs/msg/String订阅（反馈）任务状态反馈
/move_backward_distancestd_msgs/msg/UInt64发布（下发）后退距离控制，单位 cm
/move_to_posegeometry_msgs/msg/PoseStamped发布（下发）导航位移，旧接口

⚠️ 旧接口，建议使用 /start_task_v2 替代，后续版本可能移除。

任务类型（/start_task_v2 / /start_task_v2_straight） ​

所有导航任务通过下列两个 topic 下发，消息格式完全相同（task_id / type / detail 字段一致，支持的 type 也一致），外部只需切换发布的 topic 即可在两种导航策略间切换：

下发 topic路径生成跟踪方式避障典型场景
/start_task_v2A* 全局规划路径跟踪软碰撞避障普通导航（默认）
/start_task_v2_straight起点—终点直线插值直线跟踪不避障回充上桩、短距精确直行等已知无障碍场景

⚠️ 使用 /start_task_v2_straight 必读：该接口不做任何避障，机器人会沿起点→终点的直线强行走过去。下发前必须由调用方人工确认起点与终点之间的直线路径上没有任何障碍物（包括墙体、家具、临时物品等），并主动避开；如直线穿过障碍物，请改用 /start_task_v2 走 A* 规划，或先把目标点调整到一段已确认畅通的直线终点。直线模式适用于回充上桩、短距精确直行等已知无障碍的可控场景，不应用于一般导航。

任务通用格式如下：

json
{
  "task_id": "<唯一任务ID>",
  "type": "<任务类型>",
  "detail": { ... }
}

支持的任务类型：

type说明
goto_pose点到点导航（单目标）
follow_path按路径导航，依次经过每个路径点（同时兼作途经点导航）

字段类型必填说明
pose[0] (x)float是目标 X 坐标（米），地图坐标系
pose[1] (y)float是目标 Y 坐标（米），地图坐标系

follow_path — 按路径 / 途经点导航 ​

按给定顺序依次经过每个路径点，同时覆盖「严格沿路径行走」与「途经点（waypoint）导航」两种用途。具体行为由相邻路径点之间的距离自动决定，分界阈值为 0.8m：

  • 相邻点距离 ≤ 0.8m：严格 follow_path 模式，机器人按给定点逐点行走，不在点间做避障规划，要求路径本身可行。
  • 相邻点距离 > 0.8m：在每两点之间执行局部路径规划与动态避障，等同于原 navigate_through_poses 途经点导航。
json
{
  "task_id": "b1c2d3e4-0000-0000-0000-000000000001",
  "type": "follow_path",
  "detail": {
    "path": [
      {"x": 1.0, "y": 0.0, "yaw": 0.0},
      {"x": 2.0, "y": 0.5, "yaw": 0.3},
      {"x": 3.0, "y": 1.0, "yaw": 0.0}
    ]
  }
}

字段类型必填说明
patharray是路径点列表，至少 2 个点
path[].xfloat是路径点 X 坐标（米）
path[].yfloat是路径点 Y 坐标（米）
path[].yawfloat否到达该点时的朝向（弧度），缺省不约束朝向

路径点数量建议不超过 200 个，过多路径点可能影响规划性能。

严格模式（相邻点 ≤ 0.8m）下若路径点间存在障碍物，任务直接失败并通过 /task_status_v2 返回 fail；途经点模式（相邻点 > 0.8m）下若两点间规划失败或动态避障无解，同样返回 fail。

goto_base — 回充第一阶段（导航到桩前） ​

机器人自主导航到充电座正前方的对接预备点。该任务不执行上桩动作，到达后由上层下发 enter_base 完成对接。

json
{
  "task_id": "e5f6a7b8-0000-0000-0000-000000000003",
  "type": "goto_base",
  "detail": {
    "base_type": "charge",
    "is_accurate_pose": true,
    "is_base_pose": true,
    "is_allow_explore": false,
    "pose": [-0.5248, 0.0183, -0.0313]
  }
}

字段类型必填说明
base_typestring是基座类型，目前仅支持 "charge" 充电座
is_accurate_posebool是true 精确对接预备点，false 近似到达
is_base_posebool否true 表示 pose 为充电座自身坐标，规划器会在前方推算预备点；false 表示 pose 已是预备点坐标
is_allow_explorebool是充电座不可达时是否允许探索寻找
pose[x, y, yaw]是坐标（米/弧度），必须为 3 个数字的数组；含义由 is_base_pose 决定

pose 字段不可省略也不可为空数组，否则任务参数解析失败，返回 fail_reason: invalid detail。

enter_base — 回充第二阶段（上桩） ​

由 goto_base 到位后下发，执行精对位与电极对接。

json
{
  "task_id": "f7a8b9c0-0000-0000-0000-000000000004",
  "type": "enter_base",
  "detail": {
    "base_type": "charge"
  }
}

字段类型必填说明
base_typestring是基座类型，填 "charge"
remain_countsint否上桩失败时的剩余重试次数，缺省为 0（仅由内部重试逻辑使用，业务侧通常无需填写）

任务反馈复用 /task_status_v2，两阶段独立上报：上桩成功时 enter_base 的 status 为 "success"，失败时附带 fail_reason。

⚠️ 典型回充流程：先下发 goto_base（携带充电座坐标）→ 等待 status: success → 再下发 enter_base。若 goto_base 因不可达失败，可结合 is_allow_explore 触发探索，或上层重试。

任务状态反馈（/task_status_v2） ​

status说明
idle默认空状态，没有明确任务在执行
runningSDK 导航任务正在执行
success任务成功
fail任务失败，见 fail_reason
stop收到 STOP 停止命令

status 为 fail 时，fail_reason 取值：

fail_reason说明
unreachable目标不可达
invalid detail任务 detail 字段非法
no detail任务缺少 detail 字段
stop任务被 STOP 命令中止

示例命令 ​

bash
# 控制后退 25cm
ros2 topic pub --once /move_backward_distance std_msgs/msg/UInt64 "data: 25"

# 点到点导航
ros2 topic pub --once /start_task_v2 std_msgs/String "data: '{\"task_id\": \"ca76d33f-7f26-4ae8-b01b-b78de484854e\", \"type\": \"goto_pose\", \"detail\": {\"pose\": [1.0, 2.0, 0.0], \"is_accurate_pose\": true}}'"

# 点到点导航（直线模式：直线插值 + 直线跟踪 + 不避障）
# ⚠️ 调用方必须先人工确认起点到目标点的直线路径上无障碍物，否则机器人会直接撞上去
ros2 topic pub --once /start_task_v2_straight std_msgs/String "data: '{\"task_id\": \"ca76d33f-7f26-4ae8-b01b-b78de484854e\", \"type\": \"goto_pose\", \"detail\": {\"pose\": [1.0, 2.0, 0.0], \"is_accurate_pose\": true}}'"

# 按路径导航（follow_path）
ros2 topic pub --once /start_task_v2 std_msgs/String "data: '{\"task_id\": \"b1c2d3e4-0000-0000-0000-000000000001\", \"type\": \"follow_path\", \"detail\": {\"path\": [{\"x\": 1.0, \"y\": 0.0, \"yaw\": 0.0}, {\"x\": 2.0, \"y\": 0.5, \"yaw\": 0.3}, {\"x\": 3.0, \"y\": 1.0, \"yaw\": 0.0}]}}'"

# 回充第一阶段：导航到充电座前的对接预备点（pose 为已知充电座坐标）
ros2 topic pub --once /start_task_v2 std_msgs/String "data: '{\"task_id\": \"e5f6a7b8-0000-0000-0000-000000000003\", \"type\": \"goto_base\", \"detail\": {\"base_type\": \"charge\", \"is_accurate_pose\": true, \"is_base_pose\": true, \"is_allow_explore\": false, \"pose\": [-0.5248, 0.0183, -0.0313]}}'"

# 回充第二阶段：上桩（在 goto_base 成功反馈后下发）
ros2 topic pub --once /start_task_v2 std_msgs/String "data: '{\"task_id\": \"f7a8b9c0-0000-0000-0000-000000000004\", \"type\": \"enter_base\", \"detail\": {\"base_type\": \"charge\"}}'"

# 停止导航任务
ros2 topic pub --once /task_ctrl_v2 std_msgs/msg/String "{data: '{\"task_id\": \"b1c2d3e4-0000-0000-0000-000000000001\", \"cmd\": \"stop\"}'}"

# 查看任务状态反馈
ros2 topic echo /task_status_v2

ROS2 标准导航接口 ​

目标发布（调试用） ​

/goal_pose — 发布单点导航目标

  • 消息类型： geometry_msgs/msg/PoseStamped
  • frame_id： map
  • 用途： 调试时通过 RViz「2D Goal Pose」或命令行直接触发导航，等同于下发一个 goto_pose 任务
yaml
header:
  frame_id: map
pose:
  position: {x: 3.0, y: 1.5, z: 0.0}
  orientation: {x: 0.0, y: 0.0, z: 0.707, w: 0.707}   # yaw = 90°

路径规划 ​

规划路径 — nav_msgs/srv/GetPlan

  • 服务名： /planner_server/get_plan（或 /compute_path_to_pose）
  • 消息类型： nav_msgs/srv/GetPlan

请求字段：

字段类型说明
startgeometry_msgs/PoseStamped起点位姿（frame_id: map）
goalgeometry_msgs/PoseStamped目标位姿（frame_id: map）
tolerancefloat32目标被障碍物占用时允许的松弛距离（米）

响应字段：

字段类型说明
plannav_msgs/Path从起点到目标的路径点序列；为空表示规划失败

检查路径有效性 — nav2_msgs/srv/IsPathValid

  • 服务名： /is_path_valid
  • 消息类型： nav2_msgs/srv/IsPathValid

请求字段：

字段类型默认值说明
pathnav_msgs/Path—待检查的路径
max_costuint8254判定为障碍的代价阈值
consider_unknown_as_obstacleboolfalse是否将未知区域视为障碍

响应字段：

字段类型说明
is_validbool路径是否完全有效
invalid_pose_indicesint32[]无效路径点的索引列表

代价地图 ​

接口类型说明
/global_costmap/costmapTopic 订阅全局代价地图（nav2_msgs/msg/Costmap）
/local_costmap/costmapTopic 订阅局部代价地图（nav2_msgs/msg/Costmap）
/global_costmap/costmap_rawTopic 订阅全局代价地图原始数据（nav_msgs/msg/OccupancyGrid）
/local_costmap/costmap_rawTopic 订阅局部代价地图原始数据（nav_msgs/msg/OccupancyGrid）

获取代价地图 — nav2_msgs/srv/GetCostmap

  • 服务名： /global_costmap/get_costmap 或 /local_costmap/get_costmap
  • 消息类型： nav2_msgs/srv/GetCostmap
  • 请求字段： nav2_msgs/CostmapMetaData specs（可留空使用默认值）
  • 响应字段： nav2_msgs/Costmap map

清空代价地图 — nav2_msgs/srv/ClearEntireCostmap

  • 全局： /global_costmap/clear_entirely_global_costmap
  • 局部： /local_costmap/clear_entirely_local_costmap
  • 消息类型： nav2_msgs/srv/ClearEntireCostmap
  • 请求/响应： 均为空（std_msgs/Empty）

ROS2 标准导航示例命令 ​

bash
# 发布单点导航目标（调试用，等同于 goto_pose 任务）
ros2 topic pub --once /goal_pose geometry_msgs/msg/PoseStamped \
  "{header: {frame_id: map}, pose: {position: {x: 3.0, y: 1.5, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.707, w: 0.707}}}"

# 规划路径（起点→目标）
ros2 service call /planner_server/get_plan nav_msgs/srv/GetPlan \
  "{start: {header: {frame_id: map}, pose: {position: {x: 0.0, y: 0.0}, orientation: {w: 1.0}}}, \
    goal:  {header: {frame_id: map}, pose: {position: {x: 3.0, y: 1.5}, orientation: {w: 1.0}}}, \
    tolerance: 0.5}"

# 清空全局代价地图
ros2 service call /global_costmap/clear_entirely_global_costmap nav2_msgs/srv/ClearEntireCostmap "{}"

# 清空局部代价地图
ros2 service call /local_costmap/clear_entirely_local_costmap nav2_msgs/srv/ClearEntireCostmap "{}"

# 获取全局代价地图
ros2 service call /global_costmap/get_costmap nav2_msgs/srv/GetCostmap "{}"

# 查看全局代价地图话题
ros2 topic echo /global_costmap/costmap_raw --once
