使用 LeRobot 采集和回放数据 ​

OpenWonderLabs/onero_lerobot 是 Onero H1 的 LeRobot 适配器。它把机器人的 ROS 2 话题接入 LeRobot，可用于记录遥操作数据、回放 Episode、查看数据集和部署训练好的策略。

录制默认不控制机器人

默认配置下，适配器只订阅话题，不向机器人发送指令。只有加入 --send-hold-action，或把 --robot.send_action 设为 true，才会启用控制输出。

支持的数据 ​

Observation ​

数据默认话题备注
双臂关节/joint_states、/left_joint_states、/right_joint_states关节位置；力矩和帧间差可选
夹爪开合/left_gripper_state、/right_gripper_state将 UInt8 映射到 0.0-1.0
夹爪位姿/left_pose、/right_pose用于计算 diff_pos，默认关闭
升降高度/lift/joint_states默认写入 policy state
底盘里程计/agv/odom默认关闭
相机画面/head/camera/rgb、/left/camera/rgb、/right/camera/rgbCompressedImage 解码为 RGB
电池、防撞条/battery/state、/front_bumper默认关闭

默认 action 共 16 维，包括双臂 14 个关节位置和两个夹爪位置。默认 state 共 17 维，在 action 的基础上增加升降高度。

关节速度、升降动作、关节力矩、帧间差、夹爪位姿差和底盘数据均为可选项。训练和部署时必须使用同一套 observation/action 配置，否则特征维度和顺序无法对应。

控制话题 ​

开启控制输出后，适配器会使用以下话题：

部件话题消息类型备注
双臂/record_dataFloat64MultiArray默认；依次为左臂位置、左臂速度、右臂位置、右臂速度，各 7 维
双臂/left_arm/movej、/right_arm/movejString（JSON）movej 模式
夹爪/joystick_infoInt32同构遥操作时不由适配器发布
升降/lift/joint_states/updateJointState需要单独启用
头部/head/joint_states/updateJointState需要单独启用
底盘/cmd_velTwist默认关闭

MoveP、MoveL、MoveIt 2、Nav2、SLAM 地图、语音、人脸和自动回充不在这个适配器的范围内。

安装 ​

环境要求 ​

  • Ubuntu 24.04、ROS 2 Jazzy；
  • Python 3.12 或更高版本；
  • 已安装 H1 SDK，电脑可以通过 ROS 2 发现机器人话题。

适配器包本身支持 Python 3.10+，但项目固定使用的 LeRobot 0.6.1 需要 Python 3.12+。

如果 ROS 2 或 DDS 还未配置，请先完成安装 ROS 2 Jazzy和 H1 Cyclone DDS 配置。

常用参数 ​

参数默认值说明
--repo-id必填数据集 ID，例如 my_name/h1_test
--task必填任务说明，会写入每一帧
--teleop-typehomogeneous遥操作类型
--duration不限时录制时长，单位为秒
--fps30采集帧率
--camerashead,left,right要录制的相机，使用逗号分隔
--no-cameras—不录制相机
--no-gripper—不订阅夹爪 action
--root~/lerobot_datasets数据集目录
--send-hold-action—让适配器同时转发控制指令
--stop-topic/stop_recording停止不限时录制的话题

停止不限时录制 ​

不传 --duration 时，录制会一直运行。请在另一个终端发送停止消息：

bash
ros2 topic pub /stop_recording std_msgs/msg/Bool "data: true" -1
1

程序会写完当前帧再退出，避免相机图片或帧数据只写入一部分。录制程序已禁用 Ctrl+C，请使用停止话题或 --duration。

由适配器转发同构遥操作动作 ​

一般情况下不需要 --send-hold-action。如果要让适配器接管同构遥操作的手臂控制，先将主臂程序原有的 /record_data 和 /joystick_info 改名，避免两个节点同时向同一话题发消息：

bash
# 终端 1：启动主臂程序
your_leader_program \
  --ros-args \
  -r /record_data:=/leader/arm_data \
  -r /joystick_info:=/leader/joystick

# 终端 2：录制并转发手臂动作
onero-h1-record-episode \
  --repo-id my/test \
  --task "teleop test" \
  --duration 180 \
  --teleop-type homogeneous \
  --action-gripper-topic /leader/joystick \
  --send-hold-action

训练和部署策略 ​

训练部分使用 LeRobot 原有流程。开始训练前，建议先用 viz.sh 检查画面、关节顺序和动作数据。部署时的 observation/action 配置必须与训练时一致。

运行 checkpoint：

bash
source /opt/ros/${ROS_DISTRO}/setup.bash

onero-h1-lerobot-rollout \
  --strategy.type=base \
  --policy.path=/path/to/checkpoint \
  --robot.type=onero_h1 \
  --robot.id=h1 \
  --device=<cpu-or-cuda>
1

DANGER

Rollout 会实时控制机器人。适配器虽然会限制关节范围、单次变化量和底盘速度，但这些限制不能替代碰撞检测、运动规划、硬件急停和现场看护。第一次部署时应降低速度、缩短运行时间，并留出足够的安全空间。

常见问题 ​

无法导入 rclpy ​

先加载 ROS 2 环境，再确认当前 Python 能找到 rclpy：

bash
source /opt/ros/jazzy/setup.bash
python3 -c "import rclpy; print(rclpy.__file__)"
1
2

收不到机器人话题 ​

bash
ros2 topic list
ros2 topic echo /joint_states --once
ros2 topic hz /head/camera/rgb
1
2
3

如果列表中没有 H1 的话题，请检查 Cyclone DDS 配置。

相机没有画面 ​

bash
python3 -c "import cv2; print(cv2.__version__)"
ros2 topic info /head/camera/rgb -v
1
2

相机使用 SensorDataQoS 发布；适配器使用 BEST_EFFORT 订阅，两端 QoS 是匹配的。

找不到刚录制的数据集 ​

确认查看或回放时使用了相同的 --root。另外，record.sh 会把任务名追加到 repo-id，实际目录名可能与传入的 repo-id 不同。

Ctrl+C 无法停止录制 ​

这是录制器的设计。请打开另一个已加载 ROS 2 环境的终端，执行：

bash
ros2 topic pub /stop_recording std_msgs/msg/Bool "data: true" -1
1
