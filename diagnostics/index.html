系统诊断 ​

/diagnostics 是系统级诊断聚合话题，将当前启用的硬件模块、传感器、软件节点和本机系统指标统一整合后发布。它与各模块已有的独立接口（如 /arm_diagnostics、/battery/state、/body_general_control 堵转清除等）并不冲突——各模块仍然保留自己的专用接口，/diagnostics 在此基础上提供全局视图，便于开发者一站式监控整机健康状态与故障排查。

接口总览 ​

话题消息类型方向频率说明
/diagnosticsdiagnostic_msgs/msg/DiagnosticArray订阅1 Hz全局诊断聚合，包含整机 overall 和各模块状态
/diagnostic_eventsstd_msgs/msg/String订阅事件触发模块状态变化事件，data 字段为 JSON 字符串

/diagnostics 使用 TRANSIENT_LOCAL 发布，订阅方后启动时也能拿到最近一帧诊断结果。

消息格式 ​

DiagnosticArray ​

当前实现中，status[0] 固定为整机汇总项 overall，status[1...] 为各模块诊断项。DiagnosticStatus.values 是 diagnostic_msgs/msg/KeyValue[]，其中 value 均为字符串；faults、metrics、counts、group_counts、active_faults 等复杂字段以 JSON 字符串保存，订阅方需要按 JSON 解析。values 中的列表类复杂字段统一包装成 JSON object，通过 items 保存数组内容；普通模块的主故障类型合并在 faults 中：faults.primary_fault_type 表示当前主故障类型，faults.items 保存完整故障数组。

DiagnosticStatus.values 约定 ​

普通模块固定包含以下 KeyValue：

keyvalue 内容说明
h1_levelOK / WARN / ERROR / FATAL / STALE / UNKNOWNH1 内部诊断等级。FATAL 会映射为 ROS level=2，UNKNOWN 会映射为 ROS level=3
onlinetrue / false当前模块是否在线或数据是否有效
faultsJSON object 字符串当前故障详情，格式为 {"primary_fault_type": "...", "items": [...]}；items[].type 是故障类型，items[].code 是原始设备/节点错误码
metricsJSON object 字符串模块指标，例如频率、温度、fps、位置误差、原始状态等
criticaltrue / false是否为关键模块
group字符串模块分组，例如 system、base、actuator、sensor、arm、algorithm

overall 固定包含以下 KeyValue：

keyvalue 内容说明
system_level字符串整机汇总等级
task_allowedtrue / false关键模块存在 ERROR / FATAL / STALE 时为 false
countsJSON object 字符串各等级模块数量统计
group_countsJSON object 字符串各分组内的等级统计
active_faultsJSON object 字符串当前所有活动故障，格式为 {"items": [...]}；items 中每项包含来源模块名并使用 type 表示故障类型

诊断等级（level） ​

值常量含义说明
0OK正常模块运行正常
1WARN警告存在潜在问题，功能未受影响
2ERROR错误模块功能异常，需要处理
3STALE超时模块无响应或数据过期

/diagnostics 使用上表的全局健康等级。机械臂执行结果接口 /arm_diagnostics 使用执行结果语义：level=0 表示完成，level=2 表示失败，详见 执行器 — 机械臂执行反馈。 在部分 ROS2 Python 环境中，DiagnosticStatus.level 可能表现为 bytes/bytearray，订阅方应先转换成整数再比较。

电机与关节 ​

各电机模块通过 /diagnostics 上报自身状态，name 字段标识具体模块，message 字段直接描述当前状态或故障原因。

name说明典型 values 键
left_arm左机械臂h1_level, faults, metrics
right_arm右机械臂h1_level, faults, metrics
lift升降机构h1_level, faults, metrics
head头部电机h1_level, faults, metrics
base_motor_left底盘左驱动轮temperature, velocity
base_motor_right底盘右驱动轮temperature, velocity

当前默认启用 head、lift、left_arm、right_arm；base_motor_left、base_motor_right 为预留/扩展诊断项，默认不发布。 下表为故障类型说明，实际展示时建议优先读取 faults.primary_fault_type 和 faults.items[].type，message 用于人类可读的补充说明。

传感器 ​

name说明典型 values 键
lidar激光雷达metrics.rate_hz, metrics.range_count

ultrasound超声波传感器metrics.range_m

相机在线判定与雷达统一：诊断节点只订阅各相机约 1 Hz 的 fps 监控话题（std_msgs/msg/Float32），不订阅高带宽 RGB/Depth 图像流。只要 fps 话题按固定频率稳定到达即判在线（OK），不解读 fps 数值——无订阅者时相机为省带宽不出图、fps 为 0 属正常，不据此判故障。fps 话题到达频率低于最低频率（min_hz.camera，默认 0.5 Hz）判 WARN（low_rate），话题超时判 STALE。fps 数值仅作为 metrics.fps 指标透出，供观察是否掉帧。

系统诊断 ​

软件状态 ​

系统软件模块可以通过 /diagnostics 上报自身状态。当前默认启用 nav_status，其他软件状态项为扩展项，是否发布以实际启动参数和 /diagnostics.status[].name 为准。

name说明典型 values 键
nav_status导航任务状态status, task_id, fail_reason, succ_reason
slam_statusSLAM 状态status, state, error_code
slam_mapping建图状态status, state, error_code
slam_locating定位状态status, state, error_code
slam_poseSLAM 位姿输出活跃度rate_hz, position, has_nan
task_orchestrator_status任务编排状态status, state, error_code
action_status动作执行状态status, state, error_code

软件状态的原始内容通常来自 JSON 字符串或状态字符串，诊断节点会将可识别的 status、state、level、error_code、fail_reason 等字段转换为统一的 level、faults 和 metrics。其中归一化故障类型保存在 faults.primary_fault_type / faults.items[].type，原始 error_code 会保存在 faults.items[].code 或 metrics 中。

故障处理 ​

当前版本诊断聚合节点只发布 /diagnostics 和 /diagnostic_events，不提供统一的 /diagnostics/clear 清故障服务。清除故障仍应使用各模块已有的专用接口。

升降堵转报警清除 ​

升降机构有独立的堵转报警清除接口：

bash
# 清除升降堵转报警
ros2 topic pub /body_general_control std_msgs/msg/Int32 'data: 1' -1

与现有接口的关系 ​

/diagnostics 整合全系统信息，各模块原有的独立接口继续保留并正常工作：

模块接口位置说明
/arm_diagnostics执行器机械臂运动执行结果反馈（独立接口，level: 0=完成、2=失败），与 /diagnostics 并行使用
/battery/state传感器电池状态原始数据（独立接口），可作为扩展诊断输入
/chargeic_state传感器充电桩状态原始数据（独立接口），可作为扩展诊断输入
/body_general_control执行器升降堵转报警清除等控制指令（独立接口），不受 /diagnostics 影响
灯效故障指示首页 — 硬件规格红灯常亮 = 故障状态，具体触发策略以机器人整机系统配置为准

示例命令 ​

bash
# 查看全局诊断信息
ros2 topic echo /diagnostics

# 过滤查看特定模块诊断（配合 grep）
ros2 topic echo /diagnostics | grep -A 10 "left_arm"

# 查看机械臂执行结果
ros2 topic echo /arm_diagnostics

# 查看电池诊断（仅在启用 battery 诊断项时有输出）
ros2 topic echo /diagnostics | grep -A 10 "battery"

# 清除升降堵转报警
ros2 topic pub /body_general_control std_msgs/msg/Int32 'data: 1' -1

编程订阅示例（Python） ​

python
import json

import rclpy
from rclpy.node import Node
from diagnostic_msgs.msg import DiagnosticArray


def level_to_int(level):
    if isinstance(level, (bytes, bytearray)):
        return int(level[0]) if level else 0
    return int(level)


def json_value(values, key, default):
    try:
        return json.loads(values.get(key, ''))
    except (TypeError, json.JSONDecodeError):
        return default


class DiagnosticMonitor(Node):
    def __init__(self):
        super().__init__('diagnostic_monitor')
        self.sub = self.create_subscription(
            DiagnosticArray,
            '/diagnostics',
            self.callback,
            10,
        )

    def callback(self, msg: DiagnosticArray):
        for status in msg.status:
            level = level_to_int(status.level)
            values = {kv.key: kv.value for kv in status.values}

            if level >= 2:  # ERROR or STALE
                self.get_logger().error(
                    f'[{status.name}] {status.message} '
                    f'(hw_id={status.hardware_id})'
                )

                if status.name == 'overall':
                    active_faults = json_value(values, 'active_faults', {})
                    self.get_logger().error(f'  system_level: {values.get("system_level")}')
                    self.get_logger().error(f'  task_allowed: {values.get("task_allowed")}')
                    self.get_logger().error(f'  active_faults: {active_faults}')
                    continue

                metrics = json_value(values, 'metrics', {})
                faults = json_value(values, 'faults', {})
                self.get_logger().error(f'  h1_level: {values.get("h1_level")}')
                self.get_logger().error(
                    f'  primary_fault_type: {faults.get("primary_fault_type", "")}'
                )
                self.get_logger().error(f'  faults: {faults}')
                self.get_logger().error(f'  metrics: {metrics}')


def main():
    rclpy.init()
    node = DiagnosticMonitor()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()
